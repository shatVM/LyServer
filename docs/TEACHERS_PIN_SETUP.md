# Створення персонального PIN викладача локально (Issue #85)

Ця процедура — для **власника сервера**. Її мета: створити обліковий запис
викладача так, щоб персональний PIN ніколи не з'явився в браузері, мережі,
логах чи Git.

## Що де зберігається

- Облікові записи викладачів (ПІБ, дозволи, стан, **хеш** PIN) — у файлі
  `materials/.teachers.json`. Каталог `materials/` у `.gitignore`, тому файл
  ніколи не потрапить у Git. Сам PIN у відкритому вигляді не зберігається
  ніде: на сервері лише `scrypt`-хеш з унікальною сіллю.
- Адміністративний PIN (`PORTAL_PIN`) задається змінною середовища або
  генерується випадково на запуск (див. нижче).

## Крок 1. Задайте адміністративний PIN (рекомендовано)

PowerShell (поточне вікно):

```powershell
$env:PORTAL_PIN = "1234"   # приклад: власник обирає сам, ≥ 4 цифри
node server.js
```

Під час запуску сервер надрукує лише джерело значення
(`PIN викладача: задано через змінну PORTAL_PIN`), а не сам PIN.

Якщо `PORTAL_PIN` **не задано**, сервер згенерує випадковий 6-значний PIN і
покаже його **один раз лише в терміналі сервера** (рядок
`PIN для цього запуску: ......`). Це значення не потрапляє в HTTP, браузер
чи логи GitHub Actions (у CI воно взагалі не друкується). Для постійної
роботи краще задати `PORTAL_PIN` у змінних середовища, щоб PIN не змінювався
при кожному перезапуску.

## Крок 2. Створіть перший обліковий запис викладача

### Варіант A — CLI на сервері (PIN не з'являється в браузері)

```powershell
# PIN читається зі змінної TEACHER_PIN; у відповіді він не виводиться
$env:TEACHER_PIN = "1234"
node tools\teachers.js create --name "Шатківський Віталій Миколайович"
Remove-Item Env:TEACHER_PIN
node tools\teachers.js list
```

Без `TEACHER_PIN` CLI попросить ввести PIN у терміналі **без еха**
(символи не відображаються). Команда `list` показує id, ПІБ, стан і права —
ніколи PIN чи хеш.

### Варіант B — панель адміністратора

1. Увійдіть на портал за адміністративним `PORTAL_PIN` (форма «Я викладач»).
2. Відкрийте розділ **«Викладачі»** у меню.
3. Заповніть ПІБ, введіть 4-значний PIN, оберіть права (`демонстрація`,
   `матеріали`) і натисніть «Створити запис».

## Важливі правила

- Персональний PIN викладача — **рівно 4 цифри**; він **не повинен
  збігатися** з адміністративним `PORTAL_PIN` (інакше система сприйматиме
  його як адміністративний).
- PIN викладача ніколи не показується в панелі, API чи логах: адміністратор
  може лише **замінити** його (новий PIN), а не прочитати старий. Після
  заміни всі чинні сесії викладача відкликаються.
- Додавання/зняття права або деактивація запису теж відкликають чинні сесії
  негайно; вхід деактивованого чи архівованого викладача неможливий.
- Перезапуск сервера скасовує всі сесії (входи), але облікові записи
  залишаються — після перезапуску викладачі просто входять заново.

## Перевірка, що нічого не витекло

```powershell
git status            # materials/ не має бути серед змінених файлів
Select-String -Path materials\.teachers.json -Pattern "scrypt\$"   # є хеш
node tools\teachers.js list
```

## Короткий словничок

| Що | Де |
|----|----|
| Адмін-PIN | змінна `PORTAL_PIN` (або випадковий на запуск — у терміналі) |
| Персональний PIN викладача | 4 цифри; у записі лише `scrypt`-хеш |
| Записи викладачів | `materials/.teachers.json` (поза Git) |
| Панель керування | сторінка `/teachers` (лише адміністратор) |
| CLI | `node tools/teachers.js list \| create \| set-pin` |
